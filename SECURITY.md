# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются для последней опубликованной версии.

| Версия | Поддержка |
|---|---|
| `0.1.0` | Да |
| `< 0.1.0` | Нет |

## Как сообщить об уязвимости

Не создавайте публичный Issue и не прикладывайте клиентские данные.

Используйте [GitHub Private Vulnerability Reporting](https://github.com/ivan-smirnov/task-understanding/security/advisories/new). Отчёт и дальнейшее обсуждение останутся в приватном security advisory репозитория.

Укажите:

- затронутую версию и клиент;
- краткое описание риска и возможного воздействия;
- минимальные шаги воспроизведения на синтетических данных;
- ожидаемое безопасное поведение;
- известные способы снижения риска, если они есть.

Для этого проекта особенно важны обход явного вызова, выполнение инструкций из недоверенного клиентского материала, утечка данных, перезапись артефакта другой задачи и небезопасные внешние действия.

Maintainer подтвердит получение в приватном advisory и будет сообщать там о проверке и исправлении. Срок публикации согласуется после оценки риска; до выпуска исправления не раскрывайте детали публично.

Обычные ошибки и предложения направляйте в [GitHub Issues](https://github.com/ivan-smirnov/task-understanding/issues).
