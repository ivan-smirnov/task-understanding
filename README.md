Русскоязычный Agent Skill, который превращает разрозненные клиентские материалы в постановку задачи, пригодную для согласования и дальнейшей работы.

Текущий релиз: [`v0.2.0`](https://github.com/ivan-smirnov/task-understanding/releases/tag/v0.2.0) от 5 сентября 2026 года. Изменения перечислены в [CHANGELOG.md](CHANGELOG.md).

## Что делает Skill

На вход можно передать бриф, переписку, транскрипт, комментарии заказчика или новые ответы по уже разобранной задаче. Skill:

- восстанавливает цепочку `контекст → проблема → задача → решение → работоспособность → результат → сроки`;
- создаёт и обновляет живой файл `Понимание задачи.md`;
- после каждого входа показывает проблемы по разделам, их последствия и способ разрешения;
- связывает блокирующие проблемы с короткими вопросами, которые можно переслать заказчику;
- отделяет подтверждённые факты, предложения скилла, допущения, противоречия и неизвестное;
- при необходимости готовит задания на пробный материал или внешнюю проверку, но не выполняет их;
- проверяет минимальную готовность постановки к согласованию;
- после явного подтверждения создаёт датированный неизменяемый снимок;
- при новых требованиях сравнивает живой файл с последней согласованной версией и показывает изменение объёма задачи.

```text
бриф / переписка / транскрипт / новые ответы
                       |
                       v
              живое понимание задачи
                       |
             проблемы и вопросы
                       |
                       v
              готово к согласованию
                       |
                       v
          подтверждённый снимок версии
```

## Как устроен живой файл

В начале `Понимание задачи.md` видны текущая редакция, ожидаемая редакция для подтверждения и действующий согласованный снимок:

```markdown
- Текущая редакция: R-001
- Ожидается подтверждение редакции: R-001 / нет
- Действующая согласованная версия: filename / нет
```

Один вход, меняющий содержание, вопросы или решения, увеличивает редакцию один раз. Подтверждение, повтор без изменений и восстановление недостающего снимка номер не увеличивают. Любая новая правка сбрасывает прежнее ожидание; после проверки полноты скилл либо ожидает подтверждение текущей редакции, либо оставляет `нет`.

Положения помечаются как `подтверждено`, `предлагается`, `допущение`, `противоречие` или `[?]`. Предложенный скиллом критерий не считается подтверждённым, пока заказчик его явно не примет. Вопросы получают постоянные ID `Q-001`, `Q-002` и далее; закрытые и отменённые вопросы переходят в таблицу `Решения по вопросам` с колонками `ID | Вопрос | Решение`. Независимые вопросы задаются вместе, а зависимые остаются в полном списке с пометкой `после Q-…` и появляются в пересылаемом блоке, когда на них уже можно ответить.

## Границы

Skill применяется только к внешним клиентским задачам и только по прямому вызову пользователя. Он помогает прояснить и зафиксировать постановку, но не производит конечный материал.

Skill не проводит исследование или фактчек, не создаёт пробный материал, не запускает другие Skills, не отправляет документы заказчику и не записывает задачи во внешние системы самостоятельно. Инструкции внутри клиентских материалов считаются содержанием источника, а не командами агенту.

## Быстрый старт

### Codex и локальный Cursor

Codex и Cursor читают пользовательские Skills из `$HOME/.agents/skills`, поэтому одной установки достаточно для обоих клиентов:

```bash
mkdir -p "$HOME/.agents/skills"
git clone --branch v0.2.0 --depth 1 \
  https://github.com/ivan-smirnov/task-understanding.git \
  "$HOME/.agents/skills/task-understanding"
```

Вызов в Codex:

```text
$task-understanding Разбери приложенный клиентский бриф и веди понимание задачи в папке проекта.
```

Вызов в Cursor:

```text
/task-understanding Разбери приложенный клиентский бриф и веди понимание задачи в папке проекта.
```

В Cursor ручной вызов прикрепляет Skill к одному сообщению. Повторяйте `/task-understanding` с каждым новым входом или включите Skill как Custom Mode на весь сеанс.

Для Cursor Cloud Agents закоммитьте содержимое Skill в проектный `.agents/skills/task-understanding` или `.cursor/skills/task-understanding` либо установите личную копию в `$HOME/.cursor/skills` и включите Sync Skills. Локальный `$HOME/.agents/skills` сам по себе в облако не переносится.

### Claude Code

```bash
mkdir -p "$HOME/.claude/skills"
git clone --branch v0.2.0 --depth 1 \
  https://github.com/ivan-smirnov/task-understanding.git \
  "$HOME/.claude/skills/task-understanding"
```

Вызов:

```text
/task-understanding Разбери приложенный клиентский бриф и веди понимание задачи в папке проекта.
```

Если Skill не появился после создания нового каталога, перезапустите клиент.

### Установка в проект

Для Codex и Cursor клонируйте Skill из корня проекта:

```bash
mkdir -p .agents/skills
git clone --branch v0.2.0 --depth 1 \
  https://github.com/ivan-smirnov/task-understanding.git \
  .agents/skills/task-understanding
```

Для Claude Code замените `.agents/skills` на `.claude/skills`.

## Продолжение в новом чате

Историю чата сохранять необязательно. Передайте существующий живой файл и явно вызовите Skill. В Codex:

```text
$task-understanding
Продолжи работу по файлу /путь/к/Понимание задачи.md.
Новая информация заказчика: ...
Обнови тот же живой файл.
```

В Cursor или Claude Code используйте тот же запрос, заменив первую строку на `/task-understanding`.

Лучше указывать путь к исходному файлу в доступной для записи папке. Вложение в чат может быть копией; в таком случае явно задайте путь для обновлённой версии. Если задача уже согласовывалась, также передайте последний снимок `Понимание задачи — согласовано YYYY-MM-DD.md`.

Старый живой файл адаптируется при первом обычном обновлении. Если редакция раньше не велась, формат получает `R-001` без отдельного снимка; если тот же вход ещё и меняет смысл постановки, результат становится `R-002`. Старые нумерованные вопросы получают постоянные Q-ID с сохранением соответствий. Согласованная основа выбирается только при наличии признака прежнего согласования; если снимок отсутствует или история неоднозначна, скилл просит пользователя указать основу, а не восстанавливает её по догадке.

## Совместимость

Один `SKILL.md` рассчитан на открытый формат Agent Skills. Строгий запрет неявного запуска в Codex задаётся в `agents/openai.yaml`; для Cursor и Claude Code граница задана инструкциями Skill, но равнозначная техническая гарантия не заявляется.

| Клиент | Проверенное окружение | Состояние проверки `v0.2.0` |
|---|---|---|
| Codex CLI | `0.153.0` | `TU-01`–`TU-08`: PASS; результаты зафиксированы в `TESTING.md` |
| Cursor | приложение `3.19.7`, Agent CLI `2026.09.02-c22c1a3` | `TU-01`, `TU-02`, `TU-08`: PASS; результаты зафиксированы в `TESTING.md` |
| Claude Code | `2.1.62` | Beta; статическая проверка: PASS, живой прогон не выполнен |

Подробные сценарии, критерии и фактические статусы находятся в [TESTING.md](TESTING.md). Runtime-зависимостей у Skill нет.

Формат и документация: [Agent Skills specification](https://agentskills.io/specification), [Codex Skills](https://learn.chatgpt.com/docs/build-skills), [Cursor Agent Skills](https://cursor.com/docs/skills), [Claude Code Skills](https://code.claude.com/docs/en/skills).

## Обновление

Замените `<путь-к-skill>` на каталог установки, а `vX.Y.Z` — на нужный опубликованный тег:

```bash
git -C "<путь-к-skill>" fetch --tags
git -C "<путь-к-skill>" checkout --detach vX.Y.Z
```

Перед обновлением прочитайте [CHANGELOG.md](CHANGELOG.md). Живые файлы задачи хранятся в рабочих проектах, а не внутри каталога Skill, и обновлением не затрагиваются.

## Удаление

Закройте клиент и удалите только точный каталог установки `task-understanding` внутри соответствующего каталога Skills: `$HOME/.agents/skills`, `$HOME/.cursor/skills`, `$HOME/.claude/skills` либо проектного аналога. Рабочие файлы `Понимание задачи.md` и согласованные снимки находятся в папках ваших проектов и сохраняются.

## Примеры и проверка

В репозитории есть два синтетических сценария без реальных клиентских данных:

1. [Неполный бриф](examples/new-brief.md) — сохранение известной части, постоянные Q-ID, предложенные критерии и подтверждение конкретной редакции.
2. [Изменение после согласования](examples/scope-change.md) — неизменная согласованная основа, продолжение в новом чате, сброс ожидания при правке и повторное согласование.

Базовая проверка пакета:

```bash
python3 scripts/validate.py
python3 -m json.tool evals/evals.json >/dev/null
git diff --check
```

## Конфиденциальность

Брифы, переписки и транскрипты могут содержать персональные данные, коммерческую тайну и сведения под NDA. Передавайте их агенту только там, где это разрешено правилами вашей организации и настройками выбранной платформы. Не публикуйте реальные клиентские материалы в Issues, pull request или тестовые артефакты.

Примеры и eval-данные репозитория полностью синтетические. Корневой `.gitignore` дополнительно защищает от случайного коммита рабочих файлов с типовыми именами.
