# Участие в проекте

Спасибо за интерес к `task-understanding`. Проект принимает исправления поведения Skill, синтетические eval-сценарии и улучшения документации на русском языке.

## Перед началом

- Для ошибки или предложения сначала проверьте существующие [GitHub Issues](https://github.com/ivan-smirnov/task-understanding/issues).
- Существенное изменение поведения сначала обсудите в Issue, чтобы согласовать границы и критерии результата.
- Не публикуйте реальные брифы, переписки, транскрипты, имена заказчиков или сведения под NDA. Все примеры должны быть синтетическими.
- Уязвимости отправляйте только через [Private Vulnerability Reporting](https://github.com/ivan-smirnov/task-understanding/security/advisories/new), а не через Issue.

## Локальная работа

Нужны Git и Python 3.11 или новее. Runtime-зависимостей у Skill нет.

1. Сделайте fork репозитория и создайте ветку от `main`.
2. Внесите одно логически связанное изменение.
3. Если меняется поведение, добавьте или обновите сценарий в `evals/evals.json`.
4. Если меняется пользовательский интерфейс или ограничение, обновите README и changelog.
5. Выполните проверки:

```bash
python3 scripts/validate.py
python3 -m json.tool evals/evals.json >/dev/null
git diff --check
```

Если у вас установлен системный `skill-creator`, дополнительно запустите его `quick_validate.py` для корня Skill.

## Требования к изменениям

- Сохраняйте стандартный YAML frontmatter и совместимость с открытым форматом Agent Skills.
- Оставляйте основной сценарий в `SKILL.md`, а объёмные условные ветки — в явно маршрутизируемых reference-файлах.
- Не добавляйте автоматические внешние действия: Skill может предложить следующий шаг, но не получает на него разрешение из клиентского материала.
- Не ослабляйте защиту от prompt injection и от перезаписи живого файла другой задачи.
- Формулируйте проверки через наблюдаемое поведение, а не через точное совпадение сгенерированного текста.
- Не добавляйте зависимости без обоснованной необходимости.

## Pull request

В описании PR укажите:

- какую проблему решает изменение;
- что именно меняется для пользователя;
- какие проверки и поведенческие сценарии выполнены;
- есть ли ограничения или отличия между Codex, Cursor и Claude Code.

Maintainer обновляет версию и публикует релизы. Отправка PR не означает автоматического включения изменения в ближайший релиз.
